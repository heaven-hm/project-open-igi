# TerrainLightMap_Init_2 typed Frida comparison — 2026-10-21

The rebuilt Windows x86 diagnostic candidate and retail `igi.exe` passed 24/24
controlled calls to `0x004F82B0`, using the same combined probe and fixtures.
The retained JSON records executable/source/probe identities, symbol-resolved
candidate globals and entry, complete ordered inputs/outputs, process cleanup,
and the retail Escape action delivered to the IGI window.

The probe compares the entire 384-byte test context, return category/value,
stack counter, the first 20 DWORD stack entries, and the two script-mode bytes.
It exercises all combinations of the two mode bytes (0/1), enabled values
(0/1/-1), and stack positions 0/19. It runs the fixtures before the primary game thread resumes and verifies
restoration of the captured globals before startup. A clean-build receipt binds
the executable to compiler/source inputs; the candidate is staged beside retail
assets because startup resolves resources relative to the executable. Retail runs first; OpenIGI starts only after retail is gone.

This is direct native-call evidence using synthetic, nonaliasing valid contexts
inside the two running games. It does not establish natural game-loop calls,
all possible aliases/overflow, full terrain rendering, or gameplay parity.
The isolated fixture phase is recorded as `before-primary-thread-resume`.
No natural simulation-tick or thread-scheduling equivalence is claimed. No status promotion
or release acceptance follows from this result alone.

`build/runtime-traces/0x004F82B0-frida-pair-startup-failure.json`. Its Frida
callback ABI error was corrected before the successful comparison; missing
