# Ground-Truth Native Naming Divergence & Analysis Report

## 1. Why Did Ghidra/REA and IGIPatch Give Different Names?

When reverse-engineering `igi.exe`, the executable is **stripped** (there are no PDB symbols or public function export names in the retail binary). Different tools assign names based on different sources of evidence:

1. **How Ghidra/REA Named Functions (Automated Heuristics)**:
   - Automated Ghidra batch decompilation scripts group functions by **compilation unit clustering**.
   - If a function lacked an explicit string literal inside its own body, REA inherited whatever subsystem prefix appeared in the same code section or preceding translation unit (e.g. `SoundSys_`, `AI_`, `Physics_`, `Display_`).
   - Sequential numbers and placeholder actions (like `SoundSys_AttachLipsync_10`, `AI_TakeCover_22`, `Display_ClearSurfaces`) were automatically generated by REA to give every function an identifier.

2. **How IGIPatch Named Functions (Manual Dynamic & Assembly Reversing)**:
   - IGIPatch was written by **BlanknameES** specifically to patch engine bugs (e.g., the 60 FPS cap, mouse sensitivity tied to framerate, debug text rendering, widescreen aspect ratios).
   - Every address in IGIPatch was traced live in memory during game execution, cross-referenced with exact data structures, IAT imports (like `GetTickCount`), global variables (like `g_DebugTextWindow`), and Win32 handles (`g_hWnd`).
   - Therefore, **IGIPatch's names represent the TRUE semantic behavior** of what the code is actually executing.
