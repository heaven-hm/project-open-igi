# Isolated native repair loop

`python3 scripts/native_repair_loop.py --address 0x004B7570` prepares a plan from `build/native-verification.json`. The complete grouped failures remain in `build/native-repair-loop/plan.json`; one engine method is selected by default. Reference-copy failures map to the manifest's canonical engine implementation. Behavioral failures and missing runners take priority over status-only failures.

Add `--run --timeout 600` to run one repair job in a disposable replica. Supported deterministic profiles avoid a model call; other methods receive one bounded Codex CLI attempt. Installed `codex exec --help` must expose the required execution flags. The controller uses workspace-write sandboxing and automatic approval review, with no approval bypass or model override. It snapshots current dirty source, scripts, evidence and assets, excludes Git/build outputs, and links the original angr environment as read-only tooling outside the child workspace. It never launches games or applies edits to the live repository.

Each job retains `dossier.json`, `baseline/`, `workspace/`, owned child-process metadata, child JSONL, summary, `proposal.patch`, changed-file list and independent strict gate report/log. The dossier names actual existing evidence, ABI limitations and RE-Agent repository; the host agent uses actual configured MCP tools rather than an unrelated hypothesis generator. Exactly one decompiler is allowed per target, preserving the recorded provider; Binary Ninja is preferred for new analysis and Ghidra is fallback only.

The child may change only the selected implementation, its referenced evidence, its selected existing runner or a genuinely new top-level `scripts/*_runner.py`, and its address-specific scope document. Manifest edits may update only the selected record while preserving its status, all unrelated records, and root metadata. Status promotions, gate changes and unrelated source edits reject the proposal. Independent verification uses the original retail image, replica manifest, `VERIFIED`, CFG ≥0.85, semantic evidence and behavioral tests. Child claims never establish acceptance. Even a passing gate remains `candidate-review-required`; paired runtime comparisons and independent review are still necessary.

`--max-jobs N` bounds the number of one-attempt jobs. `--resume` can reuse a diagnostic proposal only when the conservative source/evidence/report/image/tool fingerprint and saved result/patch hashes match; unresolved tool identities disable reuse. Changed live inputs stop later jobs. There is no blind retry or universal-equivalence claim.

For handoff, inspect the job's `result.json`, `proposal.patch`, and strict gate log. An independent agent reviews the allowed hunks against retail evidence before applying any change; the controller performs no application, commit, push, release sealing or deployment.

Generated root build directories and Python bytecode caches are excluded from proposal diffs; source paths remain inspected. Timed-out or interrupted children produce `candidate-incomplete` and skip the independent gate. Empty run queues fail explicitly. Gate success must identify the selected source and address.

Independent gate execution is wrapped in Darwin `sandbox-exec`: writes are denied except inside the replica, the job's dedicated temporary directory, and the exact gate log/report files. Baseline, dossier and live project remain read-only. TMPDIR and Python/cache outputs are redirected without changing HOME. Without the filesystem sandbox, the generated runner is never executed. Gate-time source/evidence changes reject the proposal, and image/source hashes plus the exact one-native report must match. Shared implementation files always require a hunk-level independent critic. Interruptions stop later jobs.

A deterministic fast path precedes Codex for an exact recognized nullable 32-bit member getter whose only logic blocker is a missing behavioral runner. It requires a fresh exact-entry angr result, matching retail/source/helper hashes and CFG ≥0.85, recognizes the retail instruction bytes, and derives one unambiguous namespace/function declaration from source and header. It registers the shared `nullable_getter_diff_runner.py` only in the replica manifest, records the byte profile/offset/symbol, and uses the same sandboxed strict gate. No game logic or status is generated. Unsupported patterns retain the bounded host-agent path. Future host prompts reuse current hash-bound analysis rather than repeating setup and unrelated research.

The nullable-getter replay was exercised against `0x004B7570` using the actual compiled engine source: 17/17 concrete fixtures passed. This resolves probe coverage only; it neither promotes the native status nor proves live game parity. Concurrent source/catalog edits abort live snapshots rather than merging an inconsistent view; retry after those edits settle or validate an explicitly frozen snapshot.

A complete frozen-copy controller run selected the deterministic path with zero model calls, changed only the replica runner registration, and passed all 17 behavioral fixtures under the sandboxed gate. The gate correctly remained blocked by `STRUCTURALLY_VERIFIED < VERIFIED`; no status promotion or live manifest edit occurred. Reproducible diagnostic artifacts are retained in `docs/fidelity/evidence/native-repair-system-20261020/`. The local automation commit was attempted with normal hooks and stopped because a concurrent edit to protected `scripts/native_gate.py` disagreed with its pinned checksum; no checksum or hook was bypassed.

To discover addresses absent from the saved report, run `python3 scripts/native_repair_loop.py --discover --address 0x004137A0 --address 0x00405850 --max-jobs 2 --run`. Each address gets a fresh strict gate report. Missing manifest records become discovery dossiers listing reference hashes, possible engine address mentions, angr output, and outstanding evidence. These are leads only; the system does not invent ABI, implementation, evidence or verification status. Other registered methods continue through the isolated proposal workflow.

When a job remains blocked, `--run` exits nonzero. In the local test, both requested methods produced missing-record dossiers from strict reports; those reports showed angr 0/1, so their CFG and native behavior remain unverified. Fresh `--discover` also encountered a gate subprocess terminated with exit -9 and reported failure without accepting an incomplete report.

For a missing record, `--run` now launches a bounded, isolated analysis request that asks the available Codex MCP tools for Binary Ninja first (Ghidra only as fallback), Radare2 and angr, and reads the matching `scripts/GameNatives` references. The child saves its observations in `analysis-summary.txt` and `analysis.jsonl`; these are untrusted until checked, and the native remains blocked. The script does not directly call MCP itself. Use `--no-missing-analysis` for dossier-only operation. Tool access depends on the child Codex session and provider availability.
