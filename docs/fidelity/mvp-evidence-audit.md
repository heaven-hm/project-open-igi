# MVP evidence audit: what the labels are actually backed by

`scripts/audit_mvp_records.py` walks the 120 MVP natives and validates each
record with the gate's own `validate_report_artifact`, so a record it passes is
a record the gate would pass. It does no angr, radare2 or game work, so it is
cheap enough to run over the whole set. `docs/fidelity/mvp-record-audit.json`
holds the per-native result.

Run on the current branch:

| measure | count |
| --- | --- |
| MVP natives | 120 |
| labelled `VERIFIED` in the manifest | 78 |
| saved evidence the gate's validators accept | 70 (53 before the refresh below) |
| runner configured, so the strict gate runs it live | 119 (upper bound) |
| paired Frida evidence with calls in both images | 8 |
| records that pass the full strict gate today | 6 |

## Why 67 records are not backed

The dominant problem is not missing evidence, it is malformed saved evidence:

| cause | records |
| --- | --- |
| behavioural report does not identify the test runner | 43 |
| behavioural report's runner command is not an argv array | 8 |
| behavioural report's runner hash no longer matches `scripts/native_unicorn_runner.py` | 4 |
| implementation digest does not match the record | 1 |

`scripts/refresh_mvp_behavioral.py` was added and run to attack this directly.
It executes each record's own configured runner (with the angr and unicorn
interpreters the gate provides) and stores what the runner actually returns.

- 78 records produced a valid `behavioral-test-report` and were rebound, lifting
  saved-evidence coverage from 53 to 70.
- Three of those are new capability rather than re-plumbing: differential
  adapters were written for the Ilff chunk accessors (`0x004B7540`
  ReadContainerHeader, `0x004B7570` GetFormType, `0x004B7580` GetChunkTag), so
  those natives are now compared case by case against the retail
  instruction bytes under unicorn instead of being refused by the runner. The
  void one compares the out parameters and treats a missing return value as "not
  applicable" rather than inventing one.
- 25 records are still refused by their runner (`unsupported native address`).
- 19 records' runners ran but produced no report: missing differential adapters
  for the Ilff family, incomplete argument templates for the fpu-state and QVM
  load runners, and candidate-side build failures (uncaught exceptions, missing
  symbols) for several terrain natives.
- 1 record (`Retail_Main`) still has a stale implementation digest.

Every remaining failure is harness work — an adapter to write or a native the
candidate build cannot execute — not a relabelling exercise.

The first two are the same defect: the saved behavioural artifacts predate the
schema the gate now requires, or were produced by the generator's stub (see
`behavioral-evidence-stub-defect.md`), which carries no runner at all. The third
group is honest drift — the runner was improved after those reports were
written, so the digest they recorded is no longer the runner that would run now.

None of this is fixed by relabelling. Each affected record needs its behavioural
evidence regenerated by actually running the configured runner and storing its
real report, bound to the current implementation digest. If the runner has no
case for an address, the record cannot be backed at that pillar at all and must
say so rather than carry a plausible-looking file.

## What the end-to-end number means

8 records have a paired Frida report with positive observations on both sides.
6 of them also satisfy every other pillar and the status label, and were
re-verified with the strict gate this session:

`0x00401050` QTask_OpenEvent, `0x004CF390` DynObj_LoadModelMesh,
`0x00402880` Game_GetContext, `0x0048F170 AppContext_GetIsActive`,
`0x004B0BA0` Mem_InitHeapState, `0x004B0D40` QHash_ValueSet.

The other two are blocked by something other than evidence: Flow_RunHandler has
no behavioural runner case for a 1213-byte function with four untracked
callees, and Terrain_Load is a host-backed bridge held at ANALYZED.

## The honest summary

- "78 VERIFIED" is a label count, not an evidence count. 53 of those records
  are backed under the default definition.
- 6 natives are verified end-to-end under the definition this project actually
  needs: CFG >= 0.85, angr, a live behavioural runner and a paired Frida
  observation with calls in both images.
- The remaining work is mechanical for most records (regenerate the behavioural
  artifact from the runner) and harness work for the rest (addresses the runner
  does not support, and natives the candidate never executes).

## A runner edit invalidates every saved behavioural report

Each saved report records the runner's digest, because the report is only
trustworthy if the code that produced it is identified. That binding has a
consequence worth stating: editing the runner makes every previously saved
report stale at once. During this work the audit count visibly dropped from 68
to 50 the moment `scripts/native_unicorn_runner.py` gained the Ilff adapters,
then recovered to 70 once the refresh was re-run against the final runner.

The lesson for the campaign: finish runner changes before refreshing evidence,
or budget a full re-run (about forty addresses take a few minutes) after any
runner change. The alternative — loosening the digest binding — would destroy
exactly the property that makes these reports worth anything.
